Agent Workspace — UX redesign variants

Four directions that keep the Basalt palette (canvas #17181b · accent #4c8dff) but fix the current UX problems: repeated “Status unavailable” noise, heavy 5-line workspace cards, an empty terminal with no guidance, and weak hierarchy in the chrome. Switch variants below.

Dense single-line rail, like Zed / VS Code project lists. Max workspaces on screen, details on demand.

What changed

  • Workspace = one 30px row: status dot, name, one contextual chip
  • Paths, branch, tab chips removed from the list — shown in a hover tooltip / detail popover instead
  • Filter field replaces the “Saved layouts” block; layouts move to the ⌘K palette

Why it’s better

  • 8 workspaces used ~900px of sidebar; here they use 240px — everything scannable at once
  • Status only appears when it means something (“needs input”), killing the repeated “Status unavailable” noise
  • Central ⌘K pill makes the keyboard-first model discoverable

Trade-offs

  • Paths not visible at a glance — relies on tooltips
  • Less room for per-workspace actions; needs a context menu

What changed

  • Cards shrink from 5 lines to 2 (+1 only when there’s an alert or it’s selected)
  • Pinned / Recent groups with relative timestamps replace one flat list
  • Branch and path merge into one metadata line; tab chips only on the active card

Why it’s better

  • Keeps the at-a-glance context (path, branch) the dense variant loses
  • Recency answers “where was I?” — the most common navigation question
  • Status text appears only as an actionable alert line, in amber

Trade-offs

  • Still ~2.5× taller per item than Ledger
  • Pin management adds a small interaction surface to build

What changed

  • Sidebar removed; a titlebar workspace switcher + ⌘K palette handle all navigation
  • Empty workspace shows quick actions with shortcuts instead of a blank terminal
  • Palette unifies workspaces, layouts, and actions in one fuzzy-searchable surface

Why it’s better

  • 100% of horizontal space goes to terminals — the actual work
  • Scales to 50+ workspaces where any list UI degrades
  • Feels like Raycast/Warp/Linear — the “modern product” signal you asked for

Trade-offs

  • No ambient awareness of other workspaces’ status (needs titlebar badges)
  • Bigger departure — higher build cost and re-learning for current users

What changed

  • Sidebar is grouped by state (Active / Idle) with filter chips — not a flat alphabetical list
  • Each active row shows what the agent is doing and for how long
  • Idle workspaces collapse to a single quiet line; panes get slim headers with path + actions

Why it’s better

  • Matches the real job: monitoring several agents, jumping to the one that needs you
  • “Needs input” is a global, filterable state — never lost in the list or a buried badge
  • Idle rows stop paying the visual cost of status they don’t have

Trade-offs

  • Depends on reliable agent-status detection (currently “Status unavailable”)
  • Rows move between groups as state changes — needs careful animation to avoid jumpiness

All four variants share the Basalt token palette so any of them can be built by adjusting layout and component CSS without a re-theme. They also share three global fixes: status text only renders when actionable, the ⌘K palette is promoted to the titlebar, and empty panes always offer next actions. A/B and D can be combined (dense rows + activity grouping); C can layer on top of any of them as the keyboard path.
